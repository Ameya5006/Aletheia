# Public walkthrough media

The [69-second walkthrough](walkthrough.webm) and [poster](poster.jpg) are captured from the running [public Aletheia frontend](https://frontend.whiteflower-9d03c62c.southeastasia.azurecontainerapps.io/) at 1440 × 900. The video is assembled from sanitized browser viewport screenshots. It shows the public overview, provisioned access screen, manual entry of an illustrative case, calibrated probability, noncausal explanation, save, history, reopen, changed-input rerun, unchanged saved original, audit events and reset. The illustrative probability was 0.16546872246399696 (16.55% on screen). This is a model output for that example, not an outcome or medical recommendation.

The [recording script](../../../scripts/presentation/record-demo.mjs) accepts only the approved public frontend origin. It reads a short-lived engineer token from an ignored local file, never records the token entry, redacts identifiers, email addresses and digests in the DOM before each capture, and writes only selected sanitized JPEGs and the composed WebM here. Browser storage, private keys, token files, raw traces and temporary frames are excluded from this directory. On this managed desktop Chromium egress was blocked, so the script fulfilled browser requests with live HTTPS responses from the same approved public host; it did not replay fixtures or alter the app.

To record again, an authorized operator must have the existing signing material and provisioned engineer entitlement, refresh the ignored token with `.venv\Scripts\python.exe deployment/azure/cloud-identity.py token --role engineer`, then run `node scripts/presentation/record-demo.mjs` in an environment able to reach the public host. Review every new frame and video before sharing. The script creates new real analysis and audit records, so rerun only when that bounded demonstration is appropriate. No remote repository upload is performed by this script.

Screenshots are named in sequence; the [result](04-result.jpg), [explanation](04b-explanation.jpg), [history](06-history.jpg) and [audit trail](09-audit.jpg) are useful individual stills. The images hide operational identifiers while retaining the visible product experience. The media do not prove model validity, clinical safety or complete audit-chain verification.
